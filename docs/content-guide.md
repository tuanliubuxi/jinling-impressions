# 内容维护指南

## 资料结构

| 文件 | 内容 |
| --- | --- |
| `src/data/places.ts` | 目的地名称、区域、图片、历史、看点、走法、体力和参考来源。 |
| `src/data/city-guide.ts` | 六朝、明代、近代与城市生活的文化阅读章节。 |
| `src/data/travel-reference.ts` | 入口、开放范围、预约渠道、参考费用与核对日期。 |

资料覆盖 30 处目的地，包含经典观光、美食街巷、博物场馆、园林慢游、亲子自然与远郊山林。新增资料维护于 `expanded-places.ts`，由 `places.ts` 统一导出；图片台账为 `place-images.ts`，年代及参考图说明维护于 `image-notes.ts`。

## 来源要求

历史与运营信息优先采用政府、文旅机构、景区或场馆的官方资料，记录标题和链接。来源发布日期、信息核对日期与实际出游日期分开理解，避免将历史票价或季节公告当作实时承诺。

停留时长、体力等级、玩法、用餐思路和转场预留为编辑建议。未知预约余量、精确交通、无障碍适用和未来开放信息不由模型凭记忆补全。图片使用范围见[素材说明](assets.md)。

## 新增目的地

1. 按 `Place` 类型填写完整字段，分配唯一 ID 和真实匹配的图片。
2. 为历史、运营及数字信息补齐可追溯来源，注明适用范围。
3. 使用已有地点 ID 设置关联，确认区域与默认入口一致。
4. 补充名称、主题和常见同义词，覆盖明确点名与排除表达。
5. 更新资料覆盖检查与集成测试中的目的地清单。
6. 运行单元测试、类型检查、构建及 HTTP smoke；需要真实生成验收时显式启用 `--live`。

## 模型使用方式

检索先保留明确要求，再按主题排序，并过滤与室内、体力或预算条件冲突的候选。模型根据看点与建议走法组织具体活动；来源、入口和费用注记由服务器附加，避免生成虚构引用。主要站点数量及时间费用参考规则见[行程规划规则](planner-quality.md)。
