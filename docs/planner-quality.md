# 行程规划规则

## 生成与校验

提交后先检查输入、资料覆盖范围与可确定的条件冲突，再检索本地候选。未收录的明确目的地、预算明显冲突或资料不足的要求会在模型调用前提示调整。

模型通过 `submit_itinerary` 返回结构化参数。即使启用上游严格模式，服务器仍检查完整字段、天数、地点白名单、不重复、必选和排除项、时段顺序、秦淮夜景时段、区域折返及游览容量。

半日或少走路路线每天最多 2 个主要站点，普通一日最多 3 个。少走路过滤较高体力地点，主要游览的最短编辑时长合计不超过 240 分钟。检查通过只代表符合这些规划规则，不是实际出行可行性认证。

## 时间与费用参考

| 项目 | 当前规则 |
| --- | --- |
| 同片区衔接 | 编辑预留 15—30 分钟。 |
| 跨区衔接 | 编辑预留 45—75 分钟。 |
| 餐休、到达与返程 | 半日预留 60 分钟，一日预留 120 分钟。 |
| 参考容量 | 主要地点最短编辑停留加预留，半日不超过 240 分钟，一日不超过 660 分钟。 |
| 费用检查 | 汇总主要站点已知成人参考票价，超过预算则拒绝展示为成功。 |
| 餐饮与市内交通 | 半日 35 元、每日 70 元的编辑预留，非实际报价。 |

转场预留不来自地图计算或人工实测。参考费用不包含住宿、城际交通、购物、船票与其他可选项目；未知费用不会被当作已核实的零费用。预算低于编辑预留时提示偏紧，0 元预算不等于免费往返景点。

## 调整与版本

修改请求携带原任务编号、新要求、时长、预算与步行偏好。服务器读取已保存原方案作为上下文，新结果另建任务；原任务过期或不可用时不调用模型。

当前标签页最多保留 5 个版本，24 小时有效。切换与刷新复用结果；重新生成或修改会调用模型。明确删除的地点优先于旧要求，失败不会自动再次生成。

## 用量与边界

页面显示模型、耗时及平台返回的输入、输出和总 token。平台未返回用量时标为未知；已经返回的失败任务用量也会保存。实际金额以平台账单为准。

模型自由文本仍可能存在遗漏或事实错误。未来开放安排、预约余量、天气、无障碍适用与实时交通需按官方渠道核实。应用不进行出发位置的地理编码，也不承诺精确导航。
