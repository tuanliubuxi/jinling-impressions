# 目的地与图片扩充方案

调研日期：2026-11-16。两批目的地内容已接入，共 34 处。本文保留资料来源与取景目标；当前素材完成情况见[素材说明](assets.md)，未取得的图片仍为采集目标。

## 扩充目标

在原有 10 处目的地基础上，两批共新增 24 处，形成 34 处内容覆盖。以下分组用于维护资料与采集素材，不表示需要分批启用功能。

每处目的地至少准备 1 张主图与 3 张不同内容的副图。明孝陵、新街口、中山陵优先准备 6—8 张。图片同时回答“这是哪里”“具体看什么”“现场是什么体验”，避免连续使用同一远景的重复照片。

资料成熟度与素材成熟度分开管理：找到官方文字资料，可以进入内容编写；图片仍须逐张确认作者、许可、地点、拍摄年代与画面质量。

## 页面与内容结构

### 探索页

增加“美食街巷”“博物场馆”的分类，并保留历史、山水、街巷、地标等浏览入口。主题标签与主分类分开，允许同一目的地同时具备美食、近代、夜游、亲子等标签。

随着条目增多，按区域和主题筛选，列表只加载封面；专题入口可设置“第一次来南京”“逛吃半天”“看展与雨天备选”“城南慢游”“江岸与日落”。专题是编辑导航，不自动视为已核算路线。

### 详情页

1. 轮播主视觉、地点与区域、简短定位。
2. 图注与具体看点对应，让用户知道“到了之后看什么”。
3. 历史故事、建议游览顺序、停留与体力取舍。
4. 用餐与休息、开放和预约信息、核验日期、官方来源入口。
5. 同片区关联目的地及“以此为兴趣生成行程”的入口。

轮播支持手机滑动、前后按钮、缩略图、当前张数、键盘操作与放大查看；放大后可用 Esc 关闭并恢复焦点。默认手动切换，避免用户读图注时自动跳走。图片显示简短说明，展开后查看作者、来源和许可。

### 图片数据

保留稳定的目的地 ID；图片使用独立资产 ID，通过封面 ID 与图片 ID 数组关联。每张资产至少记录：文件路径、宽高、alt、图注、具体取景点、作者、来源页、许可及许可链接、拍摄日期（未知就写未知）、核验日期、处理说明和裁切焦点。

不要只在文档中署名：页面应能找到图片来源。将资产目录按目的地组织，浏览器使用优化后的图片；下载的多兆原图不全部纳入网页静态目录。

建议生成 WebP／AVIF 响应式资源，主视觉长边约 1600—1920 像素，副图约 1280—1600 像素，结合实际清晰度控制体积。每张常用展示资源以约 150—350 KB 为初始优化目标，最终以画面质量为准；首屏只优先加载当前图，后续按需加载，防止图片数量增加后手机首屏变慢。

## AI 规划必须同步扩充

仅增加卡片不会自动改善攻略。每个正式上线的目的地都要进入规划资料，并完成以下同步：

1. 补齐名称、别名、区域、主题、看点、建议停留和室内外属性；“逛吃”“小吃”“商场”“看展”“亲子”“近代史”等词应能召回相应地点。
2. 更新未覆盖地点的识别清单，移除已经收录的南京博物院、总统府、鸡鸣寺、红山等，避免一边能浏览、一边被提示没有资料。
3. 将明孝陵建筑、新街口铜像等设为目的地内部看点，不能把同一景区的多个照片节点排成多个主要站点或重复计算门票。
4. 扩充区域衔接和行程容量判断；牛首山、栖霞山不作为任意市区行程的顺路加游。增加目的地后复核当前候选数量上限，防止新增资料被截断而漏掉明确需求。
5. 用餐写清“在哪个片区、安排哪一餐、选择什么类型”，餐饮与购物花费分开；未经核实不承诺具体商户、人均、排队、营业或当日票务。
6. 图片资源不整体塞入模型上下文，模型读取文字看点与可追溯资料即可。

验证至少覆盖纯美食、纯购物、六朝文化、近代建筑、亲子、少走路、雨天、低预算、排除热门景点、明史与购物组合、明确点名新收录地点、远郊与市区混排、预约或闭馆冲突。主评估标准是满足需求、时间与区域合理、信息可追溯，不能只检查输出字数。
